# 월별 상환 통계 (#27)

`GET /api/payments/monthly-summary/`는 `from_month`, `to_month`(YYYY-MM), 선택 `loan_id`를 받는다. 기본값은 이번 달 포함 최근 6개월이다. 200 `PAYMENT_MONTHLY_SUMMARY_SUCCESS`; 잘못된 월/역전/중복 조회 조건은 400 `INVALID_DATE_RANGE`, 잘못된 ID는 400, 타인/없는 대출은 404다. 삭제·완납 대출의 과거 납부·적립은 포함한다. 원본/계획/revision 변경 없음.

납부는 `paid_at`, 적립은 `saved_at` 월로 집계한다. 정기 원금·추가 원금·이자·비용·적립금 사용은 별도다. `actual_amount = 납부 총액 - 적립금 사용 + 해당 월 적립 추가액`으로 기존 적립금의 출금을 새 현금 지출에 중복 합산하지 않는다. 초기 적립 자산은 해당 월 실적이 아니다. `payment_count`는 저장된 원본 건수다.

`observed`는 같은 원본 fingerprint에 대한 기록 완료/실제 0원 확인이 있고, 해당 범위 BULLET 대출들의 적립도 각각 확인된 경우만 true다. 한 건 존재/회차 PAID/자료 없음은 확인 근거가 아니다. 수정·추가·삭제로 확인이 낡으면 false, 미래 월도 false다. 관측 부족이면 실제 금액 필드들과 비율/difference는 null, 확인된 실제 0원만 0이다. 미래 날짜 원본이 섞인 손상된 원천은 503이다.

과거 목표는 실제 `PlanPresentationPort.monthViews`와 `BudgetQueryPort.monthlyOverrides`가 공급될 때만 합산한다. 현재 계획을 과거에 복제하지 않는다. 이 공급이 없으면 목표/difference는 null이다. 만기 월 BULLET의 총액은 과거 적립 자산 사용과 총 원금의 현금 차이를 확정할 원천이 없어 null을 유지한다. 적립 목표는 별도 표시할 수 있다.

월초 잔액은 이번 달에 새로 등록한 대출뿐인 범위에서는 0이다. 기존 대출이 있는 가계는 실제 `LoanQueryPort.history`의 관측 완료 월초 원천이 필요하다. 특정 기존 대출의 월초 잔액은 가계 합계로 대체하지 않고 null이다. 분모 0/원천 부족이면 원금 감소율은 null이다. 계산 가능한 경우 `(정기+추가 원금)/월초 잔액*100`, HALF_UP 소수 2자리다.

현재 런타임에는 명시적 납부/적립 관측 확인 공급 및 과거 월 목표/잔액 공통 포트 구현이 설치되지 않았다. 따라서 원본 건수와 unknown 상태는 조회 가능하지만 확인 실적·과거 비교값은 연결 전까지 null이다. 테스트 공급 대역은 격리된 테스트 문맥에만 둔다. 마이그레이션·환경변수·의존성 변경 없음.
