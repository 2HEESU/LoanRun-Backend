# 관측 실적 기반 예상 완납 계산

Issue #128의 `PlanPayoffProjection`은 [월 입력 선택](PLAN_PROJECTION_BASIS.md)을 기존 단일
`DefaultRepaymentEngine`에 연결하는 순수 개별 대출 계산기다. 공통 `RepaymentEngine`과
`FinanceModels` 계약, 기존 현금 시뮬레이션, HTTP API 및 DB는 변경하지 않는다.

## 계산 경로

1. 호출자가 기준일 현재 잔액/약정/적립 잔액, 등록일, 기준일에 유효한 소유 계획,
   독립적으로 확인한 관측 입력을 전달한다. 비활성/잔액 없는 대출과 미래 효력 계획은 거절한다.
2. 직전 6개 완료 달력 월에서 확인한 추가 원금 또는 적립액의 평균을 선택한다.
   관측이 없으면 설정된 계획을 사용한다. 둘 다 없으면 simulation=null이며 0원 계획을 만들지 않는다.
3. 기준일 이후 남은 회차에 동일 월 입력을 적용한다. 기준월에서 이미 지난 회차는 재실행하지 않는다.
   미래 입력은 예측 가정이며 납부/적립 원본으로 저장하지 않는다.
4. 기존 엔진이 동일한 이자·거치·상환 정책·만기·수수료·기간 한도 규칙으로 계산한다.

분할형 관측 `EXTRA_PRINCIPAL`은 새 Team 1 내부 엔진 입력 `simulateWithExtraPrincipal`을 사용한다.
정기 원금 적용 후 남은 원금까지 추가 원금을 상환하고, 그 원금에 대한 해당 회차 수수료를 별도로 더한다.
예: 원금 1,200원/월 정기 원금100원/월 관측 추가 원금200원/수수료10%라면 회차 추가 현금은220원이다.
저장 계획의 `EXTRA_CASH=200`은 기존 현금 입력을 사용하므로 추가 원금182원+수수료18원이다.
두 입력을 같은 대출·월에 동시에 주거나 원금을 전략 현금 pool에 섞으면 거절한다.

추가 원금이 실제 발생한 이후의 이자가 줄며, KEEP_PAYMENT/KEEP_MATURITY의 기존 정책을 유지한다.
거치 기간에는 추가 원금을 적용하지 않고 기존 GRACE_EXTRA_NOT_APPLIED 경고를 유지한다.
미확인 수수료는 FEE_UNKNOWN/GROSS_INTEREST 및 null 수수료·총현금을 유지한다.
그 경우 원금 속도에 따른 예상일을 수수료까지 검증된 가계 자금 계획으로 해석하면 안 된다.

BULLET은 관측/계획 적립을 기존 적립 입력으로 전달한다. 적립은 원금·이자를 줄이지 않으며
자금이 먼저 모여도 자동 조기상환하지 않는다. 계약 만기에 자금이 부족하면 기존 엔진의
BULLET_SAVINGS_SHORTFALL/insufficient=true/projectedPayoffDate=null을 그대로 반환한다.
지정 horizon 내 끝나지 않은 계산은 HORIZON_EXHAUSTED와 null 예상일을 유지한다.

## 통합 상태

계산기는 DB·HTTP·시스템 시각을 읽거나 상태를 저장하지 않는다. 조회 시점의 잔액과 약정,
과거 조회 근거, 월 완료 증거, 미납 정산, 현재 월 실제 사용/예산을 반영한 입력 캡처는 호출자 책임이다.
미래 전체 회차의 반복 입력 계산은 가계 cap 검증이나 이미 사용한 자금을 고려한 월별 배분 API가 아니다.
계획 원천 조회·관측 근거 공급자·공통 조회/표시 포트·API 연결과 실제 V4 적용은 후속이다.
새 HTTP 구현 수는 늘지 않으며 예상일을 원본 계획의 목표일로 덮어쓰지 않는다.

테스트는 실제 순수 엔진으로 알려진 원금/이자/수수료/현금·완납일, 관측0/fallback/입력 부족,
고정/선형/만료/미확인 수수료, 마지막 잔액 한도, 상환 정책·거치, BULLET 자금·원금 분리,
현재 회차 경과/horizon/반복 결정성, 잘못된 엔진 입력을 검증한다.

#136의 [현재 원천 조회 조합](CURRENT_PLAN_PROJECTION.md)이 실제 현재 약정/저장 계획/관측 입력을
연결한다. 추가된 projectWithUpcomingPlan은 계획 효력일 이전의 계산 회차가 없을 때만 미래 계획을
예측에 사용하며 기존 project의 미래 계획 거절 규칙은 유지한다. 부분·동결 회차/실제V4/HTTP 연결은 후속이다.
