# 대출 원장 공통 조회 — #172

`LoanLedgerQueryService`가 기존 `LoanQueryPort`의 아홉 메서드를 런타임 Bean으로 제공한다.
Team 2 예산/프로필/전략 공급자, 새 DB 테이블, 환경변수 없이 V2 원본만 읽는다. 예산/계획을
역호출하지 않고 변경·회차 생성·revision 증가도 하지 않는다. HTTP 계약/공통 DTO는 변경하지 않는다.

| 메서드 | 원천과 의미 |
|---|---|
| `terms` | 소유 대출의 현재 잔액과 약정. 현재 활성 대출의 엔진 입력은 기존 `CurrentLoanTermsQueryService` 검증 재사용. 동일 납부를 현재 잔액에서 다시 차감하지 않음 |
| `activeLoans` | 소유자의 ACTIVE 목록. 과거는 당시까지 원본이 변경되지 않았음을 확인할 수 있을 때만 제공 |
| `historicalLoans` | 범위 종료일까지 등록된 소유 대출 조건. PAID/DELETED도 포함; 과거에 변경된 현재 조건을 재사용하지 않음 |
| `dueSummary` | 실제 저장 회차의 전체 정기 부담, 정기 배분 충족/잔여, 과거 잔여, 상태별 건수. 이미 충족한 과거 의무를 다시 청구하지 않음 |
| `paymentSummary` | paid_at 기준 실제 원금/추가 원금/이자/비용/적립 사용과 현금. `cashPaid=amount-savingsUsed`. 관측 완료는 별도 증거로만 판정 |
| `savingSummary` | 최초 자산, 월 실제 적립/사용, 해당 월말 또는 오늘까지의 자산. 필요액은 약정 만기 기준이며 저장 계획/당월 override 목표와 별개 |
| `history` | 아래 명시적 관측 월 이력. 실제 잔액/납부/적립 원천 재사용 |
| `exportLoans` | 소유 대출의 실제 이름/잔액, 기간 필터 없음. PAID/DELETED 보존 |
| `exportPayments` | 소유 납부와 소유 대출 이름, paid_at 양끝 포함 필터. 비용/적립 사용 보존. 저장 계획 JSON 파싱에 의존하지 않음 |

## 확정과 불확정 경계

요약 DTO의 숫자는 기록된 원장 합계이며 `observed=false`인 월의 0은 월 실적 확정값이 아니다.
소비자는 관측 기반 지표 계산에 `observed`를 반드시 확인해야 한다. 건수/PAID/현재 값만으로 완료를
추정하지 않는다. 기존 납부/적립 증거 공급자는 여전히 별도로 필요하며 테스트 대역은 test에만 있다.

`extraCashByLoan`은 순수 EXTRA의 현금과 비용을 포함하며 사용 적립은 제외한다. REGULAR 원본에
추가 원금도 함께 있으면 비용/적립 사용이 없는 경우에만 추가 원금 현금을 확정한다. 그 외의
우선순위를 만들지 않고503이다. 정기 의무의 적립 사용도 실제 정기 배분이 한 월에 속하고 원금이
사용 적립을 충당함이 확인될 때만 제공한다. 여러 월 또는 정기/추가에 걸친 모호한 배분은503이다.

현재/미래 예산 부담에는 DELETED 대출을 제외한다. 과거 회차는 보존한다. 원래 첫 회차부터 만기
사이의 ACTIVE 대출에 대상 월 회차가 없으면 빈 의무/추정 ID를 만들지 않고503이다. 이 연결로
미생성 미래 회차 문제까지 해결된 것은 아니다. 회차 상태는 조회 시점 기준이며 과거 상태 복원이 아니다.

V2에는 과거 약정 변경 전체가 없다. 과거 기준일 뒤에 수정된 대출의 조건/ACTIVE 구성, 미래 기준일의
실제 조건, 미납/부분 납부 또는 동결 이자를 현재 엔진 입력으로 표현할 수 없는 상태는503으로 보호한다.
원천이 없는 과거를 현재 값으로 대체하지 않는다. 미래 월의 실제 적립 마감 자산도 만들지 않는다.

## 월별 이력 원천

`LoanHistoryQueryService`는 가계 또는 명시적 소유 대출을 독립 집계한다. 현재는 LoanQueryPort의
가계 메서드에 연결했으며 ReportHistoryQueryPort가 같은 계산기를 재사용할 수 있다.

- 범위에 전체가 포함된 달만 조회한다. 부분 달/미래 달의 완성 월 통계를 만들지 않는다.
- 해당 납부 범위의 명시적 완료/0 확인과, 그 달 잔액 근거가 있는 각 BULLET 대출의 적립 완료를
  모두 확인한다. 미관측 월은 HistoryMonth 행을 만들지 않으며 실적을 0으로 확정하지 않는다.
- 월초 잔액은 월초 이전 마지막 잔액 스냅샷과 이후 원금 납부로 계산한다. 현재 남은 원금은 사용하지 않는다.
- REGISTRATION의 실제 기준일이 속한 달에 그 원본 잔액을 `registeredBalance`로 제공한다.
  첫 등록 잔액 이전의 월초만 구조적 0이며, 기준 누락/중복은503이다.
- 보정 당일 납부는 원본 생성 시각으로 반영 여부를 확인한다. 시각까지 같아 불명확하면503이다.
  달 중간 보정은 이 DTO가 보정 증감을 표현하지 못하므로 관측 확정이 있어도503이다.
- 과거 대출의 현재 상태/계획 JSON과 무관하게 실제 납부/적립/잔액을 보존한다. 소유권은 모든 쿼리에 적용한다.
