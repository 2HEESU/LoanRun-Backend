# 월별 계획 표시 공통 조회 — #178

`MonthlyPlanPortService`가 기존 `PlanPresentationPort.monthViews(user,asOf,month,overrides)`를 제공한다.
예산을 조회하거나 capacity를 역호출하지 않는다. 전달받은 배분은 요청 월 표시만 변경하며 원본 계획,
당월 override 저장소, 버전, revision과 적용 이벤트는 쓰지 않는다. HTTP/공통 DTO/DB 변경 없음.

## 목표와 월 범위

- 요청 월 말에 적용되고 당시 알려진 저장 버전을 선택한다. 현재 월은 같은 버전의 기존
  `PlanViewQueryService`를 재사용한다. 다음 회차 버전과 다르면 요청 월의 원천으로 별도 표시한다.
- 다음 달 목표가 생겨도 이번 달 목표를 덮지 않는다. 등록 첫 회차가 다음 달인 경우에도 당월
  적립 override는 표시할 수 있다. 이때 아직 시작하지 않은 장기 계획과 당월 배분은 구분된다.
- BULLET 정기 이자를 미리 납부해 은행 다음 회차가 넘어가도 당월 적립 목표/아직 남은 적립 기회를
  제거하지 않는다. 필요 적립액의 달력도 정기 납부 cursor와 분리하며 은행 회차를 추가/재청구하지 않는다.
- 현재/미래 월은 현재 ACTIVE 범위이며 과거 조회는 보존된 소유 이력을 사용한다. 과거 asOf에
  나중의 완납/만기 변경을 소급해 행을 없애지 않는다. 소유권은 배분의 각 대출에도 확인한다.
- 같은 대출 중복, 음수, 방식에 맞지 않는 배분과 범위 밖 배분은 실패한다. 타인 대출은404다.
- FREE는 전체 우선순위를 숨긴다. PRO는 소유 적용 이벤트 중 요청 시점/월 경계까지 알려진 실제
  우선순위를 읽으며 미래 기록을 노출하지 않는다.

## 계산과 부족한 근거

현재 월은 기존 현재 뷰의 예측/필요 적립/원장 합계 규약을 유지한다. 현재 원장 합계가 0이어도
관측 완료로 만들지 않는다. 비교/진척/예측은 기존 근거 검증을 따르며 부족하면 null/INSUFFICIENT다.

다른 월은 캡처한 원래 약정이 있을 때만 기존 `PlanScheduleProjection`과 금융 엔진으로 월 목표를
계산한다. 현재 약정을 과거 원래 약정으로 대신하지 않는다. 기본 계획의 실제 저장 추가 목표 0은
확인된 0으로 제공하지만, 양수 현금 목표에 수수료가 불명확하면 순 추가 원금은 null이다.
현재 약정/자산으로 과거·미래 완납 예측을 채우지 않는다. 이 경우 예측 필드는 null이고 원천 경고를 제공한다.

과거 월 실적과 누적 실적은 각각의 납부/적립 확인 근거가 원본 fingerprint와 일치할 때만 확정한다.
처음 적립 자산은 월 입금 실적이 아니다. 미래 실적/미래 자산은 null이다. 과거 asOf의 수정 전 자산은
재구성할 수 없으므로 현재 자산을 노출하지 않는다. 원금 변경 시점이 확인되지 않은 과거 비율도 null이다.
최근 6개 완료월의 실제 확인 근거 수를 별도로 센다.

원래 계획의 누적 목표는 캡처한 계획 범위에서만, 누적 실제값은 해당 버전 기간 전체가 확인된 경우만
제공한다. intraday 시작 원금 대비 실적이 입증되지 않으면 actual_progress_pct는 null이다.
override가 있으면 그 월 순원금/적립 목표만 바꾸며 누적 비교에 과거 override를 임의로 가정하지 않는다.

실제 버전 테이블이 없거나 필요한 소유 원천을 읽을 수 없으면503이다. V4는 #187에서 정식
Flyway 파일로 제공되며 기존 DB 적용 여부는 별도 확인이 필요하다. 운영 관측 근거는 아직 없다.
