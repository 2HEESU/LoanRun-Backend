# 익명 사용자 데이터 삭제 (#203)

`DELETE /api/users/me/`에 `Content-Type: application/json`, `{ "confirm": true }`를 전송한다. 쓰기 요청은 기존 출처 검사에 따라 허용된 `Origin`이 필요하다. 성공은 HTTP 200, `USER_DELETE_SUCCESS`, `data.deleted=true`다. 확인값이 없거나 `true`가 아니면 HTTP 400 `CONFIRMATION_REQUIRED`와 `errors.confirm`을 반환한다. 별도 로그인/토큰은 사용하지 않는다.

현재 익명 세션 소유자의 대출·납부·적립·예산·계획·리포트·위험 이력·설정·멱등 응답을 하나의 DB 트랜잭션에서 삭제한다. 해당 브라우저 세션을 무효화하며 다음 API 요청은 신규 익명 사용자를 만든다. 공통 상품 카탈로그는 공유 데이터로 유지한다. 계획/위험 불변 이력은 V7에서 탈퇴 사용자 ID가 정확히 일치하는 삭제에만 허용한다.

프론트에서는 성공 응답을 받은 뒤 메모리 및 브라우저에 캐시한 프로필·대출·계획·예산·리포트 데이터를 지우고 온보딩 첫 화면으로 이동한다. 그 뒤 `/api/users/me/`를 새로 조회하면 새 `user_id`, `onboarding_completed=false`, `plan_type=FREE`가 반환된다. 로그아웃 버튼은 제거하고 `/api/auth/logout/`은 호출하지 않는다. 실패 시 기존 화면과 데이터를 유지하며 오류를 표시한다. 서버가 현재 세션 쿠키를 무효화하므로 요청에 기존과 동일한 쿠키 전송 설정을 유지한다.

기존 핸드오프의 ‘탈퇴 제외’는 #203 이후 이 기능에 한해 변경됐다. 실제 개발 DB의 Flyway 적용 상태를 먼저 점검해야 하며, 신규 V7 마이그레이션도 함께 적용된다.
