# 계획 계산 입력 선택

Issue #126의 `PlanProjectionBasisPolicy`는 검증된 월별 실적에서 계산 입력을 선택하는 순수 정책이다.
HTTP API, DB 변경, 공통 조회 포트 구현 또는 예상 완납 계산 자체는 추가하지 않는다.

## 관측 기간과 평균

- 기준일의 현재월을 제외한 직전 6개 완료된 달력 월만 후보로 삼는다. 예: 2026-11-19이면 5~10월.
- 대출 등록월 이전은 제외한다. 미기록 월을 채우려고 6개월보다 오래된 월을 가져오지 않는다.
- 해당 사용자·대출·지표의 기록 완료 또는 실제 0원이 독립적으로 확인된 경우만 `observed=true`다.
  원본 납부/적립 기록의 존재만으로 관측 완료를 추정하지 않는다. 미확인 입력은 금액도 null이어야 한다.
- 확인된 0원은 평균 분모에 포함하고 미확인 월은 제외한다. 1~6개 확인월의 합계를 개수로 나누며
  BigDecimal HALF_UP으로 원 단위 반올림한다. 합산 중 Long overflow를 피한다.
- 대상 지표의 같은 월 중복은 거절한다. 다른 소유자/대출 입력은 기간 밖이어도 거절한다.

## 금액의 의미와 대체 입력

| 상환 방식 | 관측 평균 | 관측이 없고 계획이 설정된 경우 |
| --- | --- | --- |
| 분할형 3종 | EXTRA_PRINCIPAL: 실제 추가 상환 원금 | EXTRA_CASH: 저장된 월 추가 납부 현금 |
| BULLET | SAVING_ADDITION: 실제 월 적립액 | SAVING_ADDITION: 저장된 월 적립 목표 |

추가 원금 평균에는 수수료를 포함하지 않는다. 계획의 납부 현금과 같은 값으로 취급할 수 없으므로
결과에 금액 종류를 명시한다. 적립 평균은 초기 자산·현재 잔액·적립금 사용액과 구분한다.
확인된 실적 0원이 있으면 양수 계획으로 대체하지 않는다. 관측이 없고 계획도 없거나 미설정이면
INSUFFICIENT/null을 반환하며, 설정된 계획의 0원은 FALLBACK_PLAN/0이다.

## 후속 연결의 책임

호출자가 기준일에 맞는 소유 계획과 상환 방식 및 검증된 관측 근거를 공급해야 한다.
현재 정책은 관측 근거를 저장/검증하거나 런타임에서 observed를 true로 만드는 공급자가 아니다.
기존 [계획 원천 조회](PLAN_SOURCE_QUERY.md)는 별도이며 이번 변경으로 API에 연결하지 않는다.
이 결과만으로 예상 완납일을 만들지 않는다. #128의 [예상 완납 계산기](PLAN_PAYOFF_PROJECTION.md)가
원금/현금 단위를 구분하여 기존 엔진의 수수료·미래 회차·BULLET 만기 부족 처리를 연결한다.
관측 근거 공급, 예산 연동과 API 응답 연결은 계속 후속 작업이다.

검증: 관측 0원/미기록, 기간·등록월·월 전환, 4개 상환 방식, 대체 계획/미설정,
반올림/큰 금액, 중복·소유권·잘못된 관측 입력을 단위 테스트한다.
