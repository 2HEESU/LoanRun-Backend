# 실제 납부 수정 (#29)

PATCH `/api/payments/{payment_id}/`는 필수 Idempotency-Key와 허용 수정 필드만 받는다. 생략은 유지, null은 nullable 구성/대상 필드만 허용한다. 실제 구성 변경은 네 항목 전체를 받아 합계를 검증하며, 총액/유형 변경에 구성값을 다시 주지 않으면 이전 수기 구성을 유지하지 않고 자동 재분리한다. loan_id/소유자/created_at 변경은 받지 않는다.

사용자 및 대출 잠금 아래 최신 스냅샷 이후의 실제 원장만 날짜/ID 순 재처리한다. 실제 다른 기록의 구성은 그대로 두고 배분·현재 잔액·적립 사용·상태·미확정 미래 회차·예산/revision을 원자적으로 갱신한다. 원래 작성 시각은 보존한다. 최신 보정에 포함된 기록과 다른 기록을 초과/모순되게 만드는 변경은409 PAYMENT_UPDATE_CONFLICT다. 입력 구성/금액 오류는400 INVALID_PAYMENT_AMOUNT다.

동일 값/빈 PATCH는 recalculated=false, report_stale=false이며 금융 원본/revision/예산을 변경하지 않는다. 멱등 요청 메타데이터는 저장한다. 실제 변경의 recalculated/report_stale는 true다. 완납 기록을 줄이면 활성 7개 제한을 확인하고 보존된 원래 회차 ID/약정/이자를 복원해 대출을 재활성화한다. 과거 회차는 보존 기록이 있을 때만 복원하며 현재 잔액으로 과거 회차를 생성하지 않는다.

BULLET 사용액 증가/일자 이동은 전체 자산 원장과 같은 날짜의 순서 불명확 경계를 검증한다. 확인할 수 없는 중간 음수 위험은409로 거절한다. 재계산 실패는 actual/배분/자산/회차/잔액/revision/멱등 응답을 모두 롤백한다. 타인 기록404, 같은 키/본문 원래 응답 재사용. 기존 회차 보존 제안 SQL을 재사용하며 새로운 Flyway/환경변수/의존성 변경 없음.
