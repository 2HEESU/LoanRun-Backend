# 상환자금 적립 수정 — API #34

`PATCH /api/repayment-savings/{saving_id}/`는 익명 세션 소유자의 활성 BULLET 적립 기록을 정정한다.
FREE/PRO 공통, 마지막 슬래시 및 Idempotency-Key(1~128자)가 필수다.

- amount: 선택, 양의 Long 정수. saved_at: 선택, 실제 존재하는 YYYY-MM-DD.
- 생략은 기존 값 유지, 명시 null은 거절한다. 빈 객체/동일 값은 무변경 요청으로 처리한다.
- 변경 후 날짜는 최신 잔액 스냅샷 날짜 이상부터 KST 오늘까지다. 스냅샷 이전 원본은 정정 날짜를
  바꾸더라도 수정할 수 없다. 같은 날짜 경계는 기존 납부/적립 조회와 동일하다.
- 생성 시각, 메모, 소유자, 대출 ID는 보존한다. 요청으로 다른 필드를 수정할 수 없다.

## 응답 및 오류

성공은 200 SAVING_UPDATE_SUCCESS, `상환자금 적립 기록 수정 성공`이다. saving과 현재 자산·필요/예정
적립액·당월 기록 합계·진행률은 기존 GET과 같은 계산이다. 과거/현재 월로 옮겨도 actual_saving_amount는
응답 시점의 KST 당월 원본 합계다. 기록 합계로 observed 또는 실제 0원 증빙을 추정하지 않는다.

- 입력/null/지원하지 않는 방식/새 날짜/키 오류: 400 SAVING_VALIDATION_ERROR,
  `만기일시상환 적립 입력값을 확인해 주세요.`.
- 타인/없는 적립 기록: 동일한 404 SAVING_NOT_FOUND, `리소스를 찾을 수 없습니다.`.
- 과거 잠금, 비활성 대출, 사용 후 잔액 부족, 순서 불명확한 위험 수정, overflow, 같은 키의 다른 본문:
  409 SAVING_CONFLICT, `적립 잔액 또는 이미 사용된 금액과 충돌합니다.`.
- 실제 변경에 필수 예산 재계산 공급자가 없으면 503 SERVICE_UNAVAILABLE/무저장이다.
- JSON 파싱, path 숫자 변환, 미디어 타입 오류는 공통 오류 처리기를 따른다.

## 사용 내역과 순서 안전성 — 2026-11-19 사용자 확정

V2는 적립과 납부에 별도 ID를 사용하므로 같은 날짜 안의 공통 거래 순서를 입증할 수 없다.
감소·날짜 지연으로 같은 날 사용 후 잔액이 음수가 될 가능성이 있는데 순서를 확인할 수 없으면
409로 거절한다. 입금이 먼저였다고 가정하거나 created_at을 실제 입출금 시각으로 해석하지 않는다.

기존 정상 원장을 확인한 뒤, 원본 적립을 대체한 날짜별 자산을 초기 자산부터 계산한다.
변경 전후의 잔액 차이로 자산이 감소할 수 있는 사용일에만 순서 검사를 적용한다. 그 날의 입금을
추가하지 않아도 시작 자산이 당일 전체 사용액을 덮으면 안전하다. 그렇지 않으면 일말 잔액이
양수여도 순서를 입증할 수 없어 409다. 같은 날짜의 금액 증가·자산을 줄이지 않는 앞당김과
수정 영향을 받지 않는 과거 사용일은 이 사유로 막지 않는다. 날짜별 음수 및 Long overflow도 거절한다.

예: 초기 자산 0, 3/2 적립100, 3/3 사용80일 때 적립90 정정은 허용, 79 또는 3/4 이동은 충돌이다.
적립과 사용이 모두 3/2이면 100→90은 순서 불명확으로 충돌하지만 100→110은 허용한다.
초기 자산100이 따로 있어 당일 사용80을 충당할 수 있으면 같은 날 100→90도 허용한다.
오류 원장을 자동 복구하거나 기존 실제 납부/배분을 바꾸는 기능은 아니다.

## 원자 처리 및 연동 상태

공통 사용자 잠금 → 본인 대출 잠금 → 본인 적립 행 잠금 → 입력·원장 검증 → 원본 수정 →
기존/새 실제 적립 월 중 이른 월부터 BudgetRecalculationPort 재계산 → RevisionPort 1회 증가 →
요약 응답 및 멱등 응답 저장을 한 트랜잭션으로 수행한다. 어느 단계든 실패하면 전부 롤백한다.
원금·이자·대출 상태·회차·실제 납부·배분·초기 자산·저장 계획을 변경하지 않는다.

빈 객체/동일 값은 자격·과거 잠금을 확인하되 원본 UPDATE, 재계산, revision 증가를 생략한다.
응답 report_stale=false는 추가 무효화를 일으키지 않았다는 뜻이며 이전 리포트가 최신이라는 선언이 아니다.
같은 키·본문은 이후 상태/스냅샷/기준일/의존성과 관계없이 최초 저장 응답을 재사용한다.
키는 사용자/PATCH/해당 적립 경로별로 분리한다. 같은 키의 다른 본문은 409다.

현재 중앙에 실제 BudgetRecalculationPort가 없으므로 실제 변경은 503/무저장이다.
적격한 무변경 요청은 공급자 없이도 200을 반환한다. 정상 변경 테스트의 예산 공급자는 테스트에만
있으며 운영 연동 완료를 의미하지 않는다. DB/Flyway/환경변수/공통 계약/의존성 변경은 없다.
