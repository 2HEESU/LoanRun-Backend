# 계획 원천 조회 조합 — Issue #124

계획 표시·성과 계산에 필요한 저장 원천을 조합하는 내부 Service다. 새 endpoint나
PlanQueryPort/PlanPresentationPort를 등록하지 않으며 기존 API를 이 Service로 전환하지 않는다.
실제 V4 적용·계획 API 연결은 여전히 후속이다.

## 두 날짜와 실제 원천

registration(user,loan)은 V2에 실제 저장된 기본 계획1번만 명시적으로 읽는다.
나중 버전이 없다는 선언이 아니다. forDate(user,loan,goalDate,knownOn)은 해당 적용일의 목표를
자료 확인 기준일(KST 날짜 말, 오늘은 현재 시각까지)로 선택한다. goalDate는 미래일 수 있지만
knownOn은 오늘 이하여야 한다. 확인 기준일 이후에 기록된 계획이나 아직 적용되지 않은 버전을
과거 목표에 섞지 않는다. 같은 효력일은 적용 가능한 가장 높은 버전이 우선한다.

선택할 저장 버전이 없으면 원래 V2 기본 계획을 그 효력일부터 사용한다. 등록 이전에 아직
존재하지 않은 목표는 Optional.empty다. 외국 소유자/없는 대출은 먼저404 LOAN_NOT_FOUND다.
PAID/DELETED도 보존된 원천을 소유자에게 읽을 수 있으며 실제 활성·성과 여부로 오인하지 않는다.

V2 시작 원금은 REGISTRATION 잔액 원본으로 읽고, 현재 잔액/최신 보정값/최초 계약 원금으로
대체하지 않는다. 근거가 없거나 해당 확인 시점에 아직 기록되지 않았다면 null이다. 모호한 중복
등록 잔액은503이다. V2에는 전체 약정/요청 스냅샷이 없으므로 basisTerms/inputs는 null이다.
새 버전의 약정/원래 입력값/전략 출처는 그 버전의 불변 원본에서 가져온다. 요청0원과 미입력 null을
보존한다. 확정 목표0과 관측되지 않은 실적0은 별개이며 실제 성과/observed/완납일을 생성하지 않는다.

## 부재와 오류

V4 버전 테이블을 읽을 수 없으면503 SERVICE_UNAVAILABLE다. 비어 있다고 가정하여 V2를 전체
최신 계획으로 반환하지 않는다. 명시적인 V2-only registration 조회는 V4 없이도 가능하다.
조회 도중 금융 원본·버전·revision을 변경하거나 SQL 제안을 자동 적용하지 않는다.

REPEATABLE_READ 읽기 전용으로 원천과 버전을 조회한다. 성과·현재 필요 적립액·은행 미래 일정·
월 override를 계산하는 API가 아니며 해당 계산기는 이 원천과 확정 실제 이력을 별도로 사용해야 한다.
실제 query/presentation 포트는 기본 계획과 이력을 조합하고 활성/과거/미래 대상을 구분한 뒤
전체 계약이 충족될 때만 등록한다. 현재 원본 소유권·확인 시점 조합이 준비되었다는 뜻이지 실제
저장/조회 endpoint가 연결되었다는 뜻은 아니다.

DB/Flyway/환경변수/의존성/공통 계약 변경 없음. 저장소 제안은 테스트 DB에서만 사용한다.
HTTP 구현 개수는 Team1 12/24, 전체20/50으로 유지한다.
