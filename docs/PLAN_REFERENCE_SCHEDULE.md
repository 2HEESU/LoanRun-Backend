# 저장 계획 기준 일정 생성

Issue #132의 `PlanScheduleProjection`은 저장된 불변 계획의 원래 약정/시작 잔액/월 목표를
기존 `RepaymentEngine`에 전달하고 `PlanPerformanceCalculator.Planned` 입력으로 조합한다.
현재 대출 약정이나 실제 속도의 예상 완납 시나리오를 과거 목표로 대신 사용하지 않는다.
DB·HTTP·시스템 시각 접근, 공통 포트 구현, Flyway 적용은 없다.

## 기준 시점과 금액

- 버전의 `basisTerms.outstanding`과 `startPrincipal`은 같아야 하며 소유자·대출이 일치해야 한다.
  저장 당시 시작 잔액을 캡처한 기준 날짜는 `recordedAt`의 KST 날짜다. 오래된 약정의 snapshotDate를
  현재 시작 잔액의 날짜로 오인하지 않는다. snapshotDate는 캡처 날짜 이후일 수 없다.
- 호출자는 약정과 시작 잔액이 해당 버전 저장 트랜잭션의 같은 상태에서 캡처되었음을 보장해야 한다.
  이 계산기는 현재 원장이나 같은 날짜 내 거래 순서를 복원하지 않는다.
- 분할형 목표는 월 **수수료 포함 현금**이다. 기존 엔진의 해당 회차 수수료를 적용한 뒤 추가 원금으로
  변환한다. 예: 월55원/수수료10%면 추가 원금50원+수수료5원이다. 현금55원을 원금 목표로 넣지 않는다.
- BULLET 목표는 월 적립액이다. 원래 적립 잔액을 사용하며 적립이 원금·이자를 줄이지 않는다.
  만기 원금 의무와 자금 부족은 구분한다. 부족해도 예정 원금 의무는 일정에 남고 예상 완납일은 null이다.

## 생성 범위와 계산 불가

반환 Planned의 범위는 계획 효력일~요청 월 말일이다. 해당 범위의 회차만 원래 엔진으로 계산하며,
계약 만기 이후에는 새 회차를 만들지 않는다. 원래 계획에서 일찍 완납되면 그 뒤 계획 목표도 없다.
요청 기간이 계약 중간에 끝나 HORIZON_EXHAUSTED가 있어도 요청 구간의 일정 생성 자체는 가능하다.
이는 해당 시점 실제 원금 상환/자금 조달이 완료되었다는 뜻이 아니다.

| 내부 Reason | 처리 |
| --- | --- |
| AVAILABLE | 기존 엔진 일정과 성과 계산용 Planned 제공 |
| NOT_CONFIGURED / NOT_EFFECTIVE | 미설정 또는 요청월 말까지 적용 전. 0원 일정으로 만들지 않음 |
| MISSING_BASIS | 원래 약정/시작 잔액 부재. V2 원천을 현재 약정으로 보충하지 않음 |
| BASIS_TIME_UNCERTAIN | 효력일 이후 캡처 또는 캡처일보다 미래인 snapshotDate |
| PRIOR_DUE_UNRESOLVED | 약정 nextDueDate가 효력일보다 이전. 납부 완료를 추정해 생략하지 않음 |
| FEE_UNCERTAIN | 추가 원금이 발생한 회차의 수수료 미확인. gross simulation만 유지하고 Planned=null |
| HORIZON_UNSUPPORTED | 원래 약정 기간이 엔진의 1~1200 달력 월 범위를 벗어남 |

이미 지난 정기 회차의 해결 여부나 다른 계획 적용 구간을 알 수 없으면 새 시작 잔액을 추정하지 않는다.
이 경우 실제 정산/기준 스냅샷 공급을 먼저 연결해야 한다. 소유권·시작 원금·적립 지표 등 모순은
입력 예외로 거절한다. 위 Reason은 내부 결과이며 새 HTTP 오류/경고 코드 계약이 아니다.

수수료를 몰라도 추가 원금이 전혀 없는 회차의 정기 원금은 확정할 수 있다. BULLET 적립 역시
추가 원금 수수료와 구분한다. 이런 경우 Planned는 제공하되 미확인 수수료/총현금은 그대로 null이다.

## 통합 상태와 검증

테스트에서 실제 엔진 → 저장 계획 일정 → 진행률 계산을 연결한다. 별도 실제 상환/적립 완료 근거는
계속 필요하며 이 일정은 observed를 true로 만들지 않는다. 현재월 override·실제 원금 감소 근거·
원천 조회 조합/공통 포트·HTTP·실제 V4 적용은 후속이다. 원본·계획·revision은 변경하지 않는다.
상환4종, 수수료/거치/정책, KST 캡처, 기간 한도, 월말, 자금 부족, 입력 모순과 결정성을 검증한다.
