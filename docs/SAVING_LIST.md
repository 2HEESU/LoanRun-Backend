# 상환자금 적립 내역 조회 — API #32

`GET /api/repayment-savings/?loan_id=...`는 익명 세션 소유자의 BULLET 대출을 조회한다.
FREE/PRO 모두 사용할 수 있다. 마지막 슬래시가 필수다. 성공은 200 `SAVING_LIST_SUCCESS`,
메시지는 `상환자금 적립 내역 조회 성공`이다.

## 입력 및 오류

- loan_id: 양의 Long, 필수. from/to: 선택, 실제 존재하는 YYYY-MM-DD 날짜. 생략하면 전체 과거부터 KST 오늘까지.
- from/to는 양끝을 포함하며 from > to는 허용하지 않는다. 빈 값, 중복 파라미터, 지정 외 파라미터는 거절한다.
- 입력 오류 또는 본인 비-BULLET 대출: 400 SAVING_VALIDATION_ERROR,
  `대출 유형과 조회 기간을 확인해 주세요.`, errors={}.
- 타인/없는 대출: 동일한 404 SAVING_NOT_FOUND, `리소스를 찾을 수 없습니다.`.
- 잘못된 저장 원본, 음수 잔액 또는 overflow: 503 SERVICE_UNAVAILABLE. 빈 성공으로 대체하지 않는다.

## 응답의 기준

- results는 선택 대출의 실제 적립 기록만 적립일·ID 오름차순으로 제공한다. from/to는 이 배열에만 적용한다.
- savings_balance는 초기 확보 자산 + 오늘까지 전체 적립 - 오늘까지 실제 납부의 적립금 사용이다.
  초기 확보 자산을 적립 거래나 당월 실적으로 만들지 않는다. 원금은 저장된 현재 잔액이며 적립 때문에 줄이지 않는다.
- actual_saving_amount는 KST 이번 달에 **기록된 적립액 합계**다. 필터로 조회한 과거 구간의 합계와 다르다.
  이 필드는 월 기록 완료 증빙이 아니다. 기록 합계가 0이어도 observed=true나 확인된 실제 0원으로 해석하지 않는다.
  관측 평균·월 완료 상태를 이 API에서 생성하지 않는다.
- required_monthly_saving은 현재 원금·적립 잔액·목표일까지 남은 적립 회차로 ceil 계산한다.
  회차가 없으면 즉시 부족액, PAID/DELETED면 0이다. 정기 이자를 미리 납부한 것만으로 적립 회차를 줄이지 않는다.
- saving_progress_pct는 잔액 / 현재 원금 × 100, HALF_UP 소수 두 자리다. 현재 원금 0이면 null이며 100%로 임의 제한하지 않는다.
- editable은 ACTIVE이며 실제 적립일이 최신 잔액 스냅샷 날짜 이상일 때 true다. 이후 쓰기 API의
  금액/사용 후 잔액/동시성 검증을 면제한다는 뜻은 아니다. 같은 날짜의 처리 기준은 기존 납부 조회와 동일하다.
- PAID/DELETED의 보존된 이력도 읽을 수 있고 editable=false다. 활성 계획·예산 조회 공급자가 없어도
  과거 이력은 읽는다. required/planned는 0, 실제 잔액/기록은 보존한다.

## 계획 및 당월 목표

현재 중앙에는 V2의 등록 시 기본 계획만 저장되어 있고 장기 변경/월 배분 쓰기 경로는 없다.
PlanQueryPort가 아직 없을 때는 이 실제 저장 기본 계획을 사용한다. 공급자가 설치되어 있으면
currentPlans의 해당 대출 계획을 사용하고 누락/중복은 503이다. 공급자 오류를 오래된 기본 계획으로 숨기지 않는다.
BudgetQueryPort가 제공하는 당월 REPAYMENT_SAVING override가 있으면 planned_saving_amount에 우선한다.
명시적 0도 적용한다. override가 없을 때만 장기 계획의 monthlySaving을 사용한다.
현재 계획/예산 공급자의 구현이나 쓰기 API를 이 작업에서 새로 등록하지 않는다.

잔액 계산은 대출 목록과 공유한다. 실제 날짜별 합산 중 이미 음수인 날은 나중 날짜의 적립으로 숨기지 않는다.
독립된 적립/납부 테이블의 ID에는 공통 순서가 없으므로 같은 실제 날짜의 합계는 그 날짜의 순변화로 읽는다.
이 읽기 모델은 당일 입출금 선후나 쓰기 원장의 완전한 재처리 검증을 대신하지 않는다.
후속 쓰기 API에서는 거래 순서/중간 잔액/동시성 검증을 별도로 완료해야 한다.

전체 조회는 REPEATABLE_READ 읽기 전용이다. 금융 원본, 계획, 회차, revision을 변경하지 않는다.
DB/Flyway/환경변수/의존성/공통 계약 변경은 없다. 적립 쓰기 #33–35, 계획 저장·진행률,
예산 재계산 연동 및 관측 증빙 입력/저장은 별도 작업이다.
