# 보유 대출 목록 — API #12

`GET /api/loans/`는 익명 세션 소유자의 대출을 조회한다. `status`는 ACTIVE(기본), PAID, ALL만
허용하며 빈 값/다른 값은 400 VALIDATION_ERROR의 `errors.status`로 반환한다. 마지막 `/`가 필수다.
FREE/PRO 모두 사용할 수 있다. 성공은 200 LOAN_LIST_SUCCESS이며 기존 공통 대출 DTO를 재사용한다.

- DELETED는 SQL에서 제외한 뒤 원본을 읽는다. ALL에는 ACTIVE/PAID만 포함한다.
- count는 선택한 상태의 목록 개수, 합계는 그 목록의 ACTIVE만 포함한다. PAID 필터의 합계는 0이다.
- 현재 remaining_principal은 저장된 현재 잔액이다. 실제 납부 원금을 다시 차감하지 않는다.
  paid_principal은 최초 원금과 현재 잔액의 차이, progress_percent는 HALF_UP 소수 2자리다.
- 현재 회차의 estimated_monthly_payment는 저장된 확정 회차의 원금+이자다. 실제 추가상환을
  하더라도 이번 회차의 확정 이자를 다시 낮추지 않는다. 완료된 회차 다음의 추정액은 동일 계산 엔진을 사용한다.
- total_monthly_due는 각 ACTIVE 대출의 다음 정기 회차 기본 필요액 합계다. 은행 입력액이 있으면
  그 회차의 필요액에 우선하며 0원도 유효하다. 이 합계는 일부 납부를 차감한 미납 잔액 합계나
  연체 누적액/추가상환/적립 계획 예산이 아니다. 그런 값은 회차·예산 조회의 별도 개념이다.
- 해당 회차가 실제 배분으로 완료되면 다음 회차를 조회하며, 완료된 회차의 은행 입력액을 다음 달로
  복제하지 않는다. 0원 회차는 그 날짜까지 0원을 유지하고 날짜가 지나면 다음 회차를 사용한다.
  일부 납부/미기록 연체 회차를 완료된 것으로 추측하지 않는다.
- V2 initial_savings_balance + 실제 적립 - 실제 사용이 적립금 잔액이다. KST 오늘 이후 실제 기록은
  포함하지 않는다. 적립은 대출 원금을 줄이지 않는다. BULLET 필요 월 적립액은 등록 기본 목표와
  남은 납부 달력 회차를 기준으로 ceil 계산한다. 후속 V4 계획 연결은 별도 작업이다.
- 실제 저장 금리 이력의 적용일·ID 순서로 최신 금리 갱신 시각을 표시한다. 이력이 없으면 시각은 null이다.
  원본 수수료 UNKNOWN/null과 면제 false/null, 상품 null을 보존한다.
- 현재 계획/확정 실적 속도를 공급하는 구현이 없으므로 estimated_payoff_date는 null이다.
  계약 만기를 실제 예상 완납일로 대체하지 않는다.

전체 원본을 REPEATABLE_READ 읽기 전용 트랜잭션으로 조회한다. 잔액·회차·계획·revision을 변경하거나
누락된 과거 실적을 0원으로 만들지 않는다. 잘못된 저장 원본, 음수 적립 자산, 금액 overflow,
복원할 수 없는 과거 기준 회차는 503이며 빈 목록/0원 성공으로 대체하지 않는다.

DB/Flyway/환경변수/의존성/공통 포트 변경은 없다. LoanQueryPort 전체 구현을 등록하는 PR이 아니므로
CSV·위험 시나리오와 예산 연동 대기는 그대로다. 등록 테스트 fixture는 실제 등록 경로를 사용하되
아직 없는 예산 재계산 provider만 테스트에서 대체하며, 운영 등록이 연동 완료되었다는 뜻이 아니다.

검증: PostgreSQL 16 Testcontainers + 고정 KST Clock + 실제 HTTP 세션으로 필터, 소유권,
빈 목록/입력 오류, 네 상환 방식, 현재 잔액, 은행 0원/null, 이번 회차 이자 보존,
배분 완료/부분 납부, 적립금 실제 일자, 월말, 오류 원본, 합계 overflow, 읽기 불변성을 확인한다.
