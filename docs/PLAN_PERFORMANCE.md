# 계획 진행률과 목표 달성 상태

Issue #130의 `PlanPerformanceCalculator`는 API #20/#23의 진행률·월별/누적 비교를 위한 순수 계산기다.
HTTP API나 공통 포트를 연결하지 않고 DB/환경변수/의존성을 변경하지 않는다.

## 입력 근거와 범위

- 설정되어 기준일에 유효한 소유 계획 원천을 받는다. 계획 시작 잔액을 최초 원금으로 대체하지 않는다.
- `Planned`는 해당 계획의 원래 약정으로 계산한 **계획 효력일~기준월 말일의 완전한 일정**이다.
  일정 행은 기존 엔진의 SimulationRow를 재사용한다. 같은 대출의 동일 날짜 중복은 거절한다.
  누락된 과거 약정/일정을 현재 약정이나 현재 목표로 재구성하지 않는다. 확보되지 않으면 null이다.
- `Actuals`는 사용자/대출/계획 버전과 시작·끝 날짜가 일치하는 확인된 실적만 받는다.
  누적 범위는 효력일~기준일, 이번 달 범위는 max(효력일,월초)~기준일이다.
  각 지표의 null은 미확인이다. 0은 실제 0원이 확인된 값이다. 개별 기록의 유무만으로 확인을 추정하지 않는다.
- 원금 진행률의 `PrincipalActual`은 해당 버전의 시작 잔액을 캡처한 시점 이후의 확인된 원금 감소다.
  목표 비교의 Actuals.principal을 그대로 대신 사용하지 않는다. 잔액 기준 시점과 효력일은 다를 수 있다.
  공급자는 같은 날짜 안의 기준 잔액/원본 순서까지 확인해야 하며 그 근거가 없으면 null이다.
- 같은 기간의 알려진 금액은 같아야 하고 이번 달 실적은 누적 실적을 넘을 수 없다.
  소유권/계획 버전/기간/중복/음수/원금 상한 및 합산 overflow를 검증한다.

이는 검증된 범위에 대한 내부 입력 계약이다. Scope나 빈 배열을 생성하는 것만으로 자료의 완전성을
입증하지 않는다. 완전한 기간을 조회했다는 근거와 월 기록 완료 확인을 확보하는 공급자는 별도 후속이다.

## 계산

| 항목 | 기준 |
| --- | --- |
| 계획 진행률 | 기준일까지 도래한 예정 정기 원금+추가 원금 합계 / 계획 시작 잔액 ×100 |
| 실제 진행률 | 해당 버전의 시작 잔액 이후 확인된 실제 상환 원금 / 같은 계획 시작 잔액 ×100 |
| 월 목표 | 기준월 전체 예정 추가 원금 또는 적립액 |
| 누적 목표 | 효력일부터 기준일까지 도래한 회차의 예정 추가 원금 또는 적립액 |
| gap | 동일 범위 확인 실적−목표 (원, signed) |
| 달성률 | 확인 실적 / 같은 범위 목표 ×100 |
| BULLET 적립 진행률 | 해당 기준일 적립 잔액 / 현재 원금 ×100 |

비율은 BigDecimal 소수 둘째 자리 HALF_UP이다. 분모0/미확인 값은 null이며 100% 초과 달성률을
임의로 자르지 않는다. 시작 원금이 없으면 계획·실제 진행률은 모두 null이나 독립적으로 확인된
추가 목표 비교는 유지할 수 있다. 수수료·이자는 원금 진행률과 추가 원금 목표에 넣지 않는다.

월 전체 목표에 미도래 회차가 있어 월 gap이 음수여도, 누적 track에는 그 미래 목표를 넣지 않는다.
납부일은 기준일까지 도래한 것으로 포함한다. track은 누적 추가 원금(BULLET은 누적 적립) gap이
0이면 ON_TRACK, 음수이면 BEHIND, 양수이면 AHEAD다. 1원 차이에도 오차 허용 없이 비교한다.
도래 목표0은 금액 비교만 하며 달성 비율은 null이다.

정기 상태가 UNRECORDED이면 track.status=UNRECORDED/data_status=INSUFFICIENT다.
그 외 비교 근거가 부족하면 status=null/INSUFFICIENT다. 비교 가능하면 SUFFICIENT이며,
정기 UNPAID/PARTIAL은 regular_due_status로 유지하고 추가 목표 상태로 바꾸지 않는다.
이 data_status는 track 비교의 충족 여부이며 모든 원금 진행률 근거의 완전성을 뜻하지 않는다.

BULLET의 적립 목표/실적에는 초기 자산과 적립금 사용액을 넣지 않는다. 초기 자산은 잔액 기반
적립 진행률에만 반영하며 원금 진행률은 실제 상환 원금을 통해서만 변한다.
지원하지 않는 추가 원금/적립 지표는 내부 Comparison의 전 필드 null이다. API 필수 0값 매핑은
향후 표시 계층에서 명세에 맞춰 처리해야 하며 미확인 실적을 임의0으로 바꾸면 안 된다.

## 통합 상태

원래 약정이 보존된 버전의 기준 일정은 #132의 [계획 일정 생성기](PLAN_REFERENCE_SCHEDULE.md)로 연결한다.
월 관측 확인 저장/공급, 과거 약정이 없는 원천의 보강과 실제 조회 조합, 현재월 예산 override,
공통 PlanPresentationPort 구현, API 응답/권한/전체 집계는 후속이다. 원본·계획·revision은 변경하지 않는다.
테스트는 기존 엔진의 원금/현금 구분 결과와 진행률, 도래일·미도래 월 목표, 1원 경계, 미기록/0원,
BULLET 적립/원금 분리, 범위·금액 오류를 검증한다.

#138의 [실제 성과 조회 조합](PLAN_PERFORMANCE_QUERY.md)은 원천과 월 확인 근거를 이 계산기에
연결한다. 시작 잔액 이후 실제 감소의 정확한 근거와 HTTP/공통 포트 연결은 계속 후속이다.
