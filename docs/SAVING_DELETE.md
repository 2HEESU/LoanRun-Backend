# 상환자금 적립 삭제 — API #35

`DELETE /api/repayment-savings/{saving_id}/`는 익명 세션 소유자의 잘못 입력한 적립 기록 한 건을
삭제한다. 본문 없음, Idempotency-Key(1~128자) 필수, FREE/PRO 공통이며 마지막 슬래시가 필요하다.
초기 확보 자산이나 대출을 삭제하는 기능은 아니다.

## 자격 및 자산 검증

본인 활성 BULLET의 실제 적립 기록만 대상이다. 원본 적립일이 최신 잔액 스냅샷 날짜 이전이면
잠겨 있으며, 같은 날짜는 기존 수정·조회와 같이 허용된다. 미래 기록/비지원 상환 방식은 거절한다.
삭제는 해당 원본 행을 제거하며 실제 납부·배분, 초기 자산, 원금·이자·대출 상태·회차·저장 계획을
변경하지 않는다. 다른 적립 기록과 생성 시각·메모는 그대로 보존한다.

기존 수정의 자산 검증을 재사용한다. 대상 적립의 기여액을 제거한 원장을 초기 자산부터 점검하여,
최종 잔액만 양수인 과거 부족도 거절한다. 사용자 확정 정책대로 같은 날 순서를 입증할 수 없는
위험 감소는409다. 당일 입금이 먼저였다고 가정하지 않는다. 이전 자산만으로 사용액을 덮는 안전한
삭제나 수정 영향을 받지 않는 과거 사용을 일괄 거절하지 않는다. 오류 원장을 자동 복구하지 않는다.

## 성공 및 오류

성공은 200 SAVING_DELETE_SUCCESS, `상환자금 적립 기록 삭제 성공`이다. data에는 saving_id,
deleted=true, loan_id, 현재 자산·필요/예정 적립액·당월 기록 합계·진행률·현재 원금,
report_stale=true를 반환한다. 요약은 GET과 동일한 계산이다. 과거 월 삭제여도 actual_saving_amount는
응답 시점 KST 당월 기록 합계이며 기록 합계로 관측 완료나 실제0원 증빙을 생성하지 않는다.

- 본문/키/비지원 방식/미래 원본: 400 SAVING_VALIDATION_ERROR,
  `만기일시상환 적립 입력값을 확인해 주세요.`.
- 타인/없는 기록: 동일한404 SAVING_NOT_FOUND, `리소스를 찾을 수 없습니다.`.
- 과거 잠금/비활성/사용 자산 부족/순서 불명확 위험 감소/같은 키의 다른 입력:
  409 SAVING_CONFLICT, `적립 잔액 또는 이미 사용된 금액과 충돌합니다.`.
- 필수 실제 예산 재계산 공급자 부재:503 SERVICE_UNAVAILABLE, 원본·revision·키 저장 변경 없음.
- path 숫자 변환 등은 공통 오류 처리기를 따른다.

## 원자 처리와 멱등성

공통 사용자 잠금 → 대출 → 적립 행 잠금 → 자격/원장 검증 → 해당 원본 삭제 → 실제 적립 월부터
예산 재계산 → revision1회 증가 → 현재 요약 및 최초 응답 저장을 한 트랜잭션으로 수행한다.
실패하면 삭제 원본과 모든 변경을 복구한다. 중간 실패한 키는 성공 응답으로 저장하지 않는다.

성공 후 같은 키/본문 없는 재요청은 이미 행이 없거나 대출 상태·기준일이 변해도 최초200을
재사용한다. 새 키로 이미 삭제된 기록에 접근하면404다. 키는 사용자/DELETE/해당 적립 경로별이다.
본문은 허용하지 않으며 명시 JSON null도 본문으로 취급한다. 최초 키로 다른 본문을 보내면409,
새 키의 본문 포함 요청은400이다. 수정/등록의 키와 범위가 겹치지 않는다.

동시 요청도 같은 사용자 잠금 안에서 최신 원장을 검증한다. 한 기록의 다른 키 삭제는200/404,
두 기록이 같은 사용액을 뒷받침하여 하나만 제거할 수 있으면200/409다. 사용 자산을 두 번 해제하거나
revision을 중복 증가시키지 않는다.

현재 실제 BudgetRecalculationPort 구현이 없으므로 유효한 삭제는503/무삭제 상태다.
성공 경로의 테스트용 공급자는 운영에 등록하지 않는다. 삭제 API 구현과 실제 예산·정산·이월 통합을
구분한다. DB/Flyway/환경변수/공통 계약/의존성 변경은 없다. 위험 이력 SQL proposal도 활성화하지 않는다.
