# 저장 계획 공통 조회 — #176

`SavedPlanPortService`가 기존 `PlanQueryPort` 세 메서드를 런타임에 제공한다. 예산을 역호출하지
않고 월 override를 장기 목표에 저장하지 않으며 금융 원본/버전/revision/전략 적용 기록을 변경하지 않는다.

| 메서드 | 실제 원천 |
|---|---|
| `currentPlans` | 소유 ACTIVE 대출의 등록 기본 계획과 불변 변경 버전 중 실제 다음 회차에 적용되는 목표. 현재 예측은 기존 PlanPayoffQueryService/엔진 재사용. 필요 적립액은 실제 자산·목표일에서 재계산 |
| `plannedAllocations` | 대상 월 말까지 효력·기록 시각이 확인되는 저장 목표와 적용 기록의 우선순위. 과거는 그 월말 이후 변경된 현재 대출 상태를 소급하지 않고 보호 |
| `overallState` | 현재 시각까지 실제 저장한 plan_application_events. 같은 소유자 이력만 사용하며 미래 시각 기록은 제외 |

저장소가 실제로 존재하지만 적용 이벤트가 없는 경우에만 overallState가 NONE이다. 테이블 부재나
DB 장애를 NONE으로 바꾸지 않는다. 현재 예측을 만들 수 없는 동결/미해결 의무에는 저장 목표를
유지하고 projectedPayoffDate만 null이다. 과거 기준일의 예측을 오늘의 지식으로 만들지 않는다.
실제 저장 회차가 0원으로 경과해 다음 회차가 확인되면 그 검증된 회차에 해당하는 목표를 선택한다.

당월 배분과 미래 효력 장기 목표는 구분된다. 새 다음 달 목표가 있어도 현재 월 배분을 바꾸지 않는다.
요청 월보다 나중에 저장된 적용 기록/현재 수정 약정을 과거 월의 근거로 사용하지 않는다.
가짜 관측 실적이나 예산 대역을 만들지 않는다. 내부 소유 원천 포트이며 HTTP 소비자의 FREE/PRO
숨김·권한 검증은 유지된다.

## V2 호환성과 DB 적용

이번 변경은 V4를 Flyway에 자동 활성화하지 않는다. Team 2 V3/V5보다 낮은 버전을 먼저 올려
기존 DB 순서를 바꾸지 않는다. 실제 적용은 `docs/MIGRATION_V2_REVIEW.md`의 검사/순서 확인이 선행된다.

기존 V2 적립 GET은 버전 포트 없이 등록 기본 계획을 읽을 수 있었다. 새 포트 설치로 이 경로가
깨지지 않도록 Team 1 내부 `RegistrationPlanFallback` capability를 추가했다. 공통 계약은 바꾸지 않는다.

- 버전/적용 테이블이 모두 없고 성공한 V4 이력도 없을 때만 기존 적립 GET이 명시적 등록 기본값을 읽는다.
- 이는 versioned port의 성공 응답이나 '이후 버전 없음'을 뜻하지 않는다. 같은 V2 환경에서 새 포트의
  비어 있지 않은 계획 조회는 필요한 버전 원천 부재로503이다.
- 테이블이 일부만 존재하면 등록 경로로 되돌아가 저장 버전을 숨기지 않는다. 각 메서드에 필요한
  실제 원천이 없으면503이다. DB 조회 장애도 fallback으로 삼키지 않는다.
- 현재 기준이 아닌 과거 상태 변경을 입증할 자료가 없으면503으로 보호한다. 빈 ACTIVE 집합의
  계획/배분만 원천상 빈 목록으로 확정할 수 있다. 전체 전략 존재 여부는 별도 저장소가 필요하다.

실제 V2 적립 HTTP 호환성, 제안 저장소 부분 적용, 저장 목표/현재 필요액 분리, 엔진 예측, 소유권,
미래 효력/적용 시각, 과거 지식 분리, 0원 회차 경과, 읽기 무변경을 PostgreSQL 테스트로 확인한다.
