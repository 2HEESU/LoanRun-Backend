# 실제 납부 등록 (#25)

POST `/api/payments/`는 필수 Idempotency-Key, 활성 소유 대출, 실제 납부일/총액/REGULAR 또는 EXTRA를 받는다. 자동 분리는 비용→이자→원금이며 정기는 가장 오래된 미충족 저장 회차부터 충당한다. 자동 분리가 실제 저장 의무를 초과하거나 구성을 확정할 수 없으면 400 INVALID_PAYMENT_AMOUNT다. 정기 원금/추가 원금/이자/비용을 실제 은행 내역으로 정정할 때는 네 항목을 모두 제공하고 합계를 확인한다. 정기 필요액에 충당되지 않는 비용을 정기 비용으로 임의 배분하지 않는다. 추가 수수료는 필요한 경우 별도 EXTRA의 실제 구성으로 기록한다. 미확인 수수료는 0으로 추측하지 않는다.

EXTRA는 원금·수수료 현금 분리를 기존 단일 엔진의 수수료 함수로 계산하고 정기 배분/상태를 바꾸지 않는다. 실제 추가 원금은 즉시 잔액에 반영한다. 기존 첫 회차 약정/이자는 보존하고, 그 회차를 완료한 뒤 생성하는 다음 회차는 갱신 잔액/정책을 사용한다. 은행 다음 납부액은 완료 후 다른 회차에 복제하지 않는다. 변경으로 더 이상 유효하지 않은 미확정 미래 회차는 제거하며 과거/실제 배분된 회차는 보존한다.

원장은 최신 잔액 스냅샷을 기준으로 실제 날짜·ID 순 재처리한다. 이전 잠금 원본과 배분은 보존하고 이후 실제 구성은 재추측하지 않는다. 현재 materialized 잔액과 기존 원장의 일치를 먼저 검증해 이중 원금 차감을 막는다. 실제 0원 잔액과 미충족 과거 의무를 함께 확인하며 미납을 삭제해 완납으로 만들지 않는다. 생성 회차는 실제 DB ID를 가진다.

BULLET 적립 사용은 해당 대출의 실제 원금 이하/자산 이내다. 같은 날짜의 입출금 순서를 확인할 수 없어 새 사용으로 중간 잔액 음수가 가능하면 409 PAYMENT_CONFLICT로 거절한다. 이전부터 순서가 불명확했던 원본을 새로 재정렬하지 않는다. 적립은 principal과 별개다.

사용자/대출 잠금, 원본, 정기 배분, 잔액/상태/다음 회차, 예산 재정산, 단일 revision 증가, 멱등 응답은 한 트랜잭션이다. 실패는 모두 롤백하며 같은 키/본문은 완료 이후에도 원래 응답을 재사용한다. 다른 세션 리소스는404다. 실제 예산/계획 공급 및 V4 DB baseline이 필요한 응답 계산이 실패하면 503/전체 롤백이다. 변경 API나 가짜 금융 공급자를 추가하지 않는다. Flyway/환경변수/의존성 변경 없음.

미확정 미래 회차를 제거할 때는 원래 약정/이자/ID를 `payment_due_archives`에 append해 이후 납부 정정/취소 시 복원한다. 보존 제안은 `docs/sql/payment_due_archives_proposal.sql`이며 실제 Flyway에 활성화하지 않았다. 이 구조가 없으면 필요한 회차 갱신/복원도 503으로 롤백한다. 특히 등록/보정 원장과 납부의 동일 시각 순서를 증명할 수 없는 보정 당일 신규 기록은409로 보류한다.
